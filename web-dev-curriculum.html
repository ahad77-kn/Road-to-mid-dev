Intermediate Track · 24 Weeks · 3 Hours Daily

Road to Mid-Level Developer

For a student who already knows basic HTML, the editor, and the browser. This path goes deep: CSS mastery, serious JavaScript, Git, React, and backend basics — with daily assignments and an exam at the end of every phase.

Daily: 1 hr learning + 2 hr assignment Weekly: 6 days study, 1 day review Exams: end of every phase
Daily rhythm: Hour 1 — study the linked material for that week. Hours 2–3 — do the assignment for that day. Assignments are listed per week; do them in order, one per day. Day 7 is for finishing anything incomplete and reviewing notes.
The one rule: No copy-paste. Type every line. If you copied it, you didn't learn it. Using documentation and searching is allowed and encouraged — that's what real developers do.
Phase 1 · CSS Mastery (Weeks 1–3)
WEEK 1

CSS Fundamentals & Box Model

Goal: understand exactly why elements sit where they sit.

Most self-taught developers stay weak at CSS forever because they guess instead of understanding. Selectors, specificity, the box model, and units are the foundation — master them now and layout stops being a mystery.

Learning (1 hr/day)

  • MDN: CSS styling basics — main material this week
  • web.dev: Box model — read twice

Assignments (2 hr/day)

  • D1 Recreate a business card as HTML/CSS — exact spacing, borders, colours.
  • D2 Build a pricing card (title, price, feature list, button) using only padding/margin — no flexbox yet.
  • D3 Take yesterday's card, break it 5 ways on purpose (wrong specificity, collapsed margins…), then fix each. Write one line per bug explaining it.
  • D4 Typography page: article layout with proper font sizes, line-height, and spacing using rem only.
  • D5 Recreate the header of any news website (Dawn, BBC) — logo left, links right — with inline-block/floats to feel the pain flexbox solves.
  • D6 Style a full signup form: focus states, error state (red border + message), disabled button.
WEEK 2

Flexbox & Grid

Goal: build any layout you see, from memory, in under 30 minutes.

Flexbox for one dimension, Grid for two. These two systems are 90% of modern layout work. The games below make the properties stick; the assignments make them permanent.

Learning (1 hr/day)

  • Flexbox Froggy — finish all levels, day 1–2
  • Grid Garden — finish all levels, day 3–4
  • CSS-Tricks: Complete Flexbox guide — keep open as reference
  • CSS-Tricks: Complete Grid guide — reference

Assignments (2 hr/day)

  • D1 Redo the Week-1 news header in flexbox. Compare — write 3 sentences on the difference.
  • D2 Card gallery: 6 cards in a flex row that wraps, equal heights, even gaps.
  • D3 Holy-grail layout in Grid: header, sidebar, main, footer.
  • D4 Photo gallery in Grid where some images span 2 columns/rows (like Instagram explore).
  • D5 Full landing page top section: nav + hero with text left, image right.
  • D6 Recreate the YouTube home layout skeleton (sidebar + video grid) with dummy boxes.
WEEK 3

Responsive Design & Polish

Goal: one codebase, perfect on a phone and a laptop.

Half the internet in Pakistan is mobile-only. Media queries, mobile-first thinking, fluid units, and responsive images are not optional skills — they are the job.

Learning (1 hr/day)

  • web.dev: Learn Responsive Design — main material
  • MDN: Responsive design — second pass

Assignments (2 hr/day)

  • D1 Make the Week-2 landing page fully responsive: hero stacks on mobile, nav collapses to a simple menu.
  • D2 Card gallery responsive: 1 column phone, 2 tablet, 3 desktop — using Grid auto-fit/minmax, no media queries.
  • D3 Add transitions and hover effects to every interactive element on the landing page. Subtle, not circus.
  • D4–D6 Phase project: full multi-section portfolio site — hero, about, projects grid, contact form. Pixel-clean, responsive, deployed thinking (organised files).
Phase 1 Exam — 3 hours, closed notes
Give him a screenshot of any real website section (pick one yourself — a hero + card grid works well). He must recreate it responsive without looking at the site's code. Passing: layout matches on mobile + desktop, clean class names, no absolute-positioning hacks.
Phase 2 · JavaScript, Seriously (Weeks 4–9)
WEEKS 4–5

Language Fundamentals

Goal: solve small logic problems in JS without help.

This is where students quit — the jump from markup to programming. Two full weeks on pure language: variables, types, conditions, loops, functions, arrays, objects. No DOM yet. Console only. Slow is fast here.

Learning (1 hr/day)

  • JavaScript.info Part 1, ch. 2–5 — the core material, read + type every example
  • freeCodeCamp JS sections — extra reps when a topic feels shaky

Assignments (2 hr/day, examples per topic)

  • W4 D1–D2 10 small console programs: grade calculator, odd/even, biggest of three, multiplication table, etc.
  • W4 D3–D4 Loop drills: sum 1–100, reverse a string, count vowels, FizzBuzz, print patterns (triangle of stars).
  • W4 D5–D6 Functions: rewrite all previous drills as functions with parameters and return values.
  • W5 D1–D3 Arrays: build a student-marks program — add marks, average, highest, lowest, filter passed students. Use map/filter/reduce by D3.
  • W5 D4–D6 Objects: contact book in the console — add, search, delete, list contacts (array of objects).
WEEKS 6–7

DOM & Events

Goal: connect JS logic to the page — real interactive apps.

The DOM is where JavaScript meets his HTML/CSS skills. Selecting elements, changing them, listening for clicks and input. From here every assignment is a visible app.

Learning (1 hr/day)

  • JavaScript.info Part 2: Document — DOM chapters
  • MDN: Introduction to events

Assignments (2 hr/day)

  • W6 D1 Counter app: +, −, reset buttons; number turns red below zero.
  • W6 D2–D3 Full calculator with clickable buttons (his CSS skills style it).
  • W6 D4–D6 To-do list: add, delete, mark done, count remaining. Rebuild it from scratch on D6 without looking at D5's code.
  • W7 D1–D2 Form validation: signup form with live inline errors (email format, password length, matching passwords).
  • W7 D3–D4 Quiz app: questions from an array of objects, score at the end.
  • W7 D5–D6 Image slider/carousel with next, previous, and dots. No library.
WEEKS 8–9

Modern JS, Async & APIs

Goal: fetch real data, handle failure, and use the JS every codebase uses today.

ES6+ (destructuring, template literals, spread, modules), then the hard one: asynchronous code — promises, async/await, fetch. This is the exact skill that separates tutorial-followers from developers.

Learning (1 hr/day)

  • JavaScript.info: Promises, async/await — main material, weeks' hardest reading
  • MDN: Using Fetch
  • public-apis list — free APIs for assignments

Assignments (2 hr/day)

  • W8 D1–D2 Refactor the quiz + to-do apps into ES6: arrow functions, template literals, destructuring, modules.
  • W8 D3–D4 Random-user cards: fetch from randomuser.me, render cards, "load more" button, loading spinner.
  • W8 D5–D6 Weather app with Open-Meteo: city search, current weather, error message for bad input.
  • W9 D1–D3 Movie search with OMDb API (free key): search, results grid, detail view.
  • W9 D4–D6 Phase project: currency converter or prayer-times app (AlAdhan API) — his choice, built alone.
Phase 2 Exam — two parts
Part A (1 hr, no internet): 5 logic problems on paper/console — e.g. reverse words in a sentence, find duplicates in an array, sum nested object values. Part B (2 hr, docs allowed): build a small app against an API he hasn't used, from a one-paragraph spec you write. Passing: working app + he can explain every line out loud.
Phase 3 · Professional Tooling (Weeks 10–11)
WEEKS 10–11

Git, GitHub, npm & DevTools

Goal: work like a professional — version control, branches, published code.

No mid-level developer works without Git. Two weeks: commits, branches, merges, pull requests, plus npm basics and real debugging in browser DevTools. From now on, every assignment is committed to GitHub with proper messages — that becomes his public portfolio.

Learning (1 hr/day)

  • Pro Git, ch. 1–3 — free book, main material
  • Learn Git Branching — interactive, do "Main" sequence
  • GitHub: Pull requests docs
  • Chrome DevTools docs — Elements, Console, Network, Sources tabs

Assignments (2 hr/day)

  • W10 Push all previous projects to GitHub (one repo each, real READMEs). Deploy the 3 best on GitHub Pages. Daily: one Learn-Git-Branching level set.
  • W11 D1–D3 Branch workflow drill: for one project, every change = branch → commit → PR → merge. You (teacher) review the PRs and request changes at least once.
  • W11 D4–D6 Debugging drills: you break his old projects (3 bugs each), he finds them using DevTools breakpoints — no console.log allowed.
Phase 3 Exam — practical
Give him a repo with a bug and a feature request. He must: clone, branch, fix the bug, add the feature, open a PR with a clear description. Passing: clean history, working code, readable PR.
Phase 4 · React (Weeks 12–17)
WEEKS 12–14

React Fundamentals

Goal: think in components — props, state, and rendering lists.

React is the most in-demand frontend skill in job listings (Pakistan and remote). The official docs are now genuinely the best course. Components, JSX, props, state, events, conditional rendering, lists.

Learning (1 hr/day)

  • react.dev: Learn React — main course, "Describing the UI" + "Adding Interactivity"
  • Vite guide — how to start React projects

Assignments (2 hr/day)

  • W12 Rebuild the counter, then a profile-card component reused 5 times with different props, then a togglable FAQ accordion.
  • W13 Rebuild the to-do app in React (D1–D3), then the quiz app in React (D4–D6). Rebuilding known apps isolates the "React way" as the only new thing.
  • W14 Multi-component app: expense tracker — add expense form, list, total, filter by category. Lifted state, controlled inputs.
WEEKS 15–17

React with Data & Routing

Goal: real multi-page React apps that fetch and manage server data.

useEffect, data fetching, custom hooks, React Router for multiple pages, and useContext for shared state. This is mid-level frontend territory.

Learning (1 hr/day)

  • react.dev: Escape Hatches (useEffect)
  • React Router docs
  • react.dev: Context

Assignments (2 hr/day)

  • W15 Rebuild the movie-search app in React with a custom useFetch hook, loading and error states.
  • W16 Add React Router: home, search, movie-detail page (/movie/:id), favourites page. Favourites in Context.
  • W17 Phase project: a small e-commerce front (fake store API: fakestoreapi.com) — product grid, detail page, cart with Context, deployed on Netlify or Vercel.
Phase 4 Exam — 3 hours, docs allowed
Spec you write: a 2-page React app against any public API with routing, loading/error states, and one piece of shared state. He builds it live while explaining decisions. Passing: it works, components are sensibly split, no state bugs.
Phase 5 · Backend Basics (Weeks 18–21)
WEEKS 18–19

Node.js & Express

Goal: build the APIs he has been consuming.

A mid-level developer understands both sides of fetch. Node runs his JavaScript on a server; Express turns it into an API: routes, request/response, middleware, JSON.

Learning (1 hr/day)

  • Node.js official Learn — intro chapters
  • Express: Getting started
  • MDN: Express/Node tutorial — main structured course

Assignments (2 hr/day)

  • W18 Hello-world server → JSON API for the to-do app: GET, POST, DELETE, PUT routes with an in-memory array. Test with Postman or curl.
  • W19 Add middleware: logging, input validation, error handling, 404s. Then connect his React to-do frontend to his own API — full stack for the first time.
WEEKS 20–21

Database & Auth Basics

Goal: data that survives a restart, and users that log in.

SQLite first — it's a real SQL database with zero setup, perfect for learning. Then password hashing and JWT login, the minimum a mid-level dev must understand about auth.

Learning (1 hr/day)

  • SQLite Tutorial — SELECT/INSERT/UPDATE/DELETE/JOIN basics
  • better-sqlite3 — use from Node
  • JWT introduction

Assignments (2 hr/day)

  • W20 Replace the in-memory to-do array with SQLite. Daily SQL drills (10 queries/day on a sample DB you give him).
  • W21 Add signup/login with hashed passwords (bcrypt) and JWT; each user sees only their own todos.
Phase 5 Exam — take-home, 2 days
Spec: a notes API (users, login, CRUD notes, SQLite) + minimal React frontend. Then a 30-minute viva: you ask him to explain auth flow, one SQL query, and one middleware, and to add one small feature live. Passing: secure, working, explained.
Phase 6 · Capstone (Weeks 22–24)
WEEKS 22–24

One Real Project, Shipped

Goal: a deployed full-stack app he designed, built, and can defend in an interview.

Three weeks, one project of his own choosing that needs everything: React frontend, Express API, database, auth, Git workflow with branches, deployed live. Ideas: a class result-management system, a small marketplace, a hostel mess-management app — local problems make the best portfolios.

Support material

  • Render docs — free backend hosting
  • Vercel docs — frontend hosting
  • Conventional Commits — commit message standard

Structure

  • W22 Plan (features list, simple wireframes, DB schema on paper — you approve it) + build the API.
  • W23 Build the frontend, connect everything, auth working end to end.
  • W24 Polish, fix, write a proper README with screenshots, deploy, and prepare a 10-minute demo presentation.
Final Exam — demo + defence
He presents the live app for 10 minutes, then 30 minutes of questions: "why this schema?", "what happens if the token expires?", "make this button do X — live." Passing this = he is genuinely at junior-to-mid level and ready for real freelance work or internships.

After Graduation

Portfolio: GitHub with 24 weeks of commits + a deployed capstone. Next moves: TypeScript (official handbook), testing with Vitest, and start bidding small Fiverr/Upwork jobs — real clients teach what no course can.
